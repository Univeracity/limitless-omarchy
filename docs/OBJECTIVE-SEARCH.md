# Objective search in the development branch

The next coordinated release adds `limitless_check` alongside the existing
structured and Omarchy customization tools. Installed older clients retain
their original query surface. The released 0.2.1 bundle does not yet contain
this development implementation.

The model provides one concise objective. The public Library kernel searches
existing native catalog projections and original generic captures, returns one
method or component to verify, or abstains. It retains a private continuation
with the underlying decision. Neither query fetches components, installs files,
nor executes verification.

Omarchy supplies its existing native profile for local desktop work. Explicit
owner-configured remote targets take precedence; the agent host's platform,
Python version, and shell are not substituted for the receiving program.
Exact selection remains off until explicitly configured. Methods are guidance
to apply freshly and check, not evidence that the task already succeeded.

The panel's **Check reusable work** action and connected agents use the same
saved search preference. Local matches avoid a service request. **Include
public Library when needed** permits concise objectives to be sent when local
work does not fit; the owner can turn this off even while the service is
unavailable. Activation alone does not grant this consent. Method sharing still
requires its separate destination and publication-policy authorization.

The query preference is a separate `query-policy.json` beside the existing
settings. It is reloaded on each query, and checked again before an objective
transfer. Old settings, installation keys, drafts, projections, and signed
publication records are not migrated or rewritten. The original `panel-state`
command retains `limitless.omarchy-panel-state/0.1`; `panel-overview` separately
adds query consent under version 0.2.

Long-lived connections use the Library's read-only catalog snapshot. External
registration, supersession, and retirement refresh the next query. Changed
exact files require digest validation; damaged or busy sources cannot serve
their preceding selection. Independently valid core captures remain usable,
with partial coverage visible. Query readers do not create writer locks or
edit method records. The snapshot follows the 2,000-record native draft bound.

The old `query`, `service-query`, `provider`, and registration inputs remain
available. Lower-level `check` accepts a bounded JSON line with only an
`objective`; `query-policy-show` and `query-policy-apply` inspect or save the
separate preference. Advanced receiver policy remains the Library's shared
contract, rather than a second Omarchy policy implementation.

Qualification still requires coordinated candidate bundles, installed-client
continuity, native rendering, and actual receiver reuse. Source-level tests
alone do not establish release readiness.

The core now also owns immutable native draft registration and revisions.
Omarchy supplies its original compatibility projection and sharing initializer;
record schemas, ULID identities, signed publication state, and old result fields
stay intact. Retrying a successful revision preserves its ID. Interrupted
projection retirement can be completed without rewriting its records.

After applying and checking a selected method, the panel can keep **Worked
after checking** or **Needs adaptation** as private self-reported feedback.
Connected agents use the same core `limitless_record_outcome` tool. Reports bind
to the content and receiver in the private continuation, never publish notes,
and never increment verified-adoption claims. The old registration and sharing
interfaces remain available.
